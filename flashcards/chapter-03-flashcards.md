## Chapter 3: IaaS, PaaS, SaaS and Cloud Service Models — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the customer's OS management responsibility in IaaS vs PaaS vs SaaS? | IaaS: Customer patches and manages OS. PaaS: Microsoft manages OS, customer manages application. SaaS: Microsoft manages everything. Exam tip: OS patching responsibility is the key differentiator—only IaaS requires customer to patch OS. |
| 2 | Azure SQL Database vs SQL Server on Azure VM - which is IaaS and which is PaaS? | SQL Server on Azure VM = IaaS (full OS access, customer manages patches). Azure SQL Database = PaaS (no OS access, Microsoft manages infrastructure). Exam tip: Need OS-level access or custom agents? = IaaS. Just need a database? = PaaS. |
| 3 | What is a 'lift-and-shift' migration and which service model does it use? | Lift-and-shift = moving existing applications to cloud with minimal changes. Uses IaaS (Azure VMs) because existing apps require OS control. Exam tip: Lift-and-shift = IaaS. Cloud-native development = PaaS. |
| 4 | Which cloud service model provides the MOST customer control: IaaS, PaaS, or SaaS? | IaaS provides most control (manage OS, networking, storage). PaaS = less control (manage app only). SaaS = least control (consume only). Exam tip: More control = more responsibility for patching and security. |
| 5 | Microsoft 365 and Dynamics 365 - which service model? | Both are SaaS. Customer consumes applications via subscription. Microsoft manages everything: infrastructure, platform, and application. Exam tip: If it ends in '365' or is Microsoft's app you just use = SaaS. |
| 6 | Who manages identity and access management in IaaS, PaaS, and SaaS? | Customer manages identity and access in ALL THREE service models. This includes user accounts, permissions, MFA, conditional access. Exam tip: Identity is ALWAYS customer's responsibility regardless of service model. |
| 7 | Azure App Service - IaaS or PaaS? What does customer NOT manage? | Azure App Service = PaaS. Customer does NOT manage: OS, runtime patches, infrastructure scaling, load balancing. Customer manages: application code, app settings, deployment. Exam tip: No SSH access = likely PaaS. |
| 8 | When should you choose IaaS over PaaS? | Choose IaaS when: 1) Need OS-level access, 2) Custom drivers/kernel modules required, 3) Lift-and-shift migration, 4) Legacy apps that can't be modified. Exam tip: 'Need to install custom software on OS' = IaaS. |
| 9 | When should you choose PaaS over IaaS? | Choose PaaS when: 1) Building new/cloud-native apps, 2) Want automatic scaling, 3) Focus on code not infrastructure, 4) No need for OS access. Exam tip: 'Developers want to focus on code' = PaaS. |
| 10 | Who manages physical datacenter security in all cloud service models? | Microsoft (cloud provider) manages physical security in ALL service models (IaaS, PaaS, SaaS). Includes: datacenter access, physical network, host infrastructure. Exam tip: Physical layer is ALWAYS provider's responsibility. |
| 11 | What are the three main examples of IaaS services in Azure? | 1) Azure Virtual Machines, 2) Azure Virtual Networks (VNets), 3) Azure Storage (Blobs, Disks). Customer controls OS, networking configs, storage management. Exam tip: If it says 'Virtual' and you configure it = likely IaaS. |
| 12 | What are the three main examples of PaaS services in Azure? | 1) Azure App Service (web apps), 2) Azure SQL Database, 3) Azure Functions (serverless). Customer manages app/data only. Microsoft manages infrastructure. Exam tip: Managed database or app platform = PaaS. |
