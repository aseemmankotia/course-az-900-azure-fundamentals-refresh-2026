## Chapter 8: Azure Governance, Monitoring, and Management Tools — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Azure Policy vs RBAC vs Resource Locks: What's the difference? | Azure Policy = WHAT (enforces configuration standards, e.g., 'all VMs must have backup enabled'). RBAC = WHO (controls permissions, e.g., 'Bob can create VMs'). Resource Locks = CHANGE PREVENTION (prevents deletion/modification, e.g., 'can't delete this resource group'). Exam tip: Policy enforces compliance, RBAC controls access, Locks prevent accidents. |
| 2 | Two types of Azure Resource Locks and what they prevent? | CanNotDelete: prevents deletion, allows modifications. ReadOnly: prevents deletion AND modifications (full read-only). Exam tip: ReadOnly is more restrictive. Locks apply to all users, even owners. Common mistake: thinking RBAC can override locks - it cannot. |
| 3 | Azure Advisor vs Azure Monitor vs Azure Service Health: Which detects platform outages? | Azure Service Health = detects Azure platform outages, planned maintenance, and health advisories for YOUR resources. Azure Monitor = collects metrics/logs from resources (performance/availability). Azure Advisor = personalized best practice recommendations. Exam tip: 'Outage notification' = Service Health, 'Performance metrics' = Monitor, 'Cost recommendations' = Advisor. |
| 4 | What is ARM template declarative syntax vs imperative scripting? | Declarative (ARM/Bicep): you define WHAT you want ('I want a VM with these specs'), Azure figures out HOW. Imperative (scripts): you define step-by-step HOW to create it. Exam tip: ARM templates are declarative, idempotent (can run multiple times safely). JSON format (ARM) or simplified syntax (Bicep). |
| 5 | Azure Arc core capability? | Projects non-Azure resources (on-premises servers, AWS VMs, Kubernetes clusters) into Azure Resource Manager. Enables Azure Policy, RBAC, tags, and Azure management tools on hybrid/multi-cloud resources. Exam tip: 'Manage AWS with Azure Policy' = Azure Arc. Brings Azure governance to anywhere. |
| 6 | Application Insights vs Azure Monitor: Which tracks distributed tracing? | Application Insights = APM (application performance monitoring) with distributed tracing, dependency tracking, anomaly detection. Azure Monitor = platform service that collects metrics/logs; Application Insights is a feature OF Azure Monitor. Exam tip: 'Track request flow through microservices' = Application Insights. |
| 7 | Microsoft Purview core function? | Unified data governance: discovers, classifies, and manages data across Azure, multi-cloud, and on-premises. Automated data scanning, sensitivity labeling, compliance reporting, data cataloging. Exam tip: 'Classify sensitive data across entire data estate' = Purview. Not just Azure security - it's data governance. |
| 8 | Azure CLI vs Azure PowerShell vs Cloud Shell: What's Cloud Shell? | Cloud Shell = browser-based shell in Azure Portal with Azure CLI and PowerShell pre-installed. No local installation needed. Includes 5GB free storage. Azure CLI = cross-platform command-line (bash syntax). PowerShell = Windows-focused cmdlets. Exam tip: Cloud Shell = managed environment, CLI/PowerShell = tools available in Cloud Shell or locally. |
| 9 | Azure Policy effect types: Deny vs Audit vs DeployIfNotExists? | Deny = blocks non-compliant resource creation. Audit = logs non-compliance but allows creation. DeployIfNotExists = automatically deploys missing resources (e.g., diagnostic settings). Exam tip: 'Prevent creation' = Deny, 'Report violations' = Audit, 'Auto-remediate' = DeployIfNotExists. |
| 10 | Bicep vs ARM templates: What's the relationship? | Bicep = simplified language for ARM templates. Bicep compiles to ARM JSON. Easier syntax, better tooling, less verbose. Same capabilities as ARM. Exam tip: Bicep is Azure's recommended IaC language over raw ARM JSON. Both are declarative and deploy to ARM. |
| 11 | Five Azure Advisor recommendation categories? | 1. Cost (savings opportunities), 2. Security (vulnerabilities), 3. Reliability (availability improvements), 4. Operational Excellence (process/workflow), 5. Performance (speed/responsiveness). Exam tip: Advisor is FREE and analyzes your specific resources. Recommendations are personalized, not generic. |
| 12 | Log Analytics workspace role in Azure Monitor? | Central repository for log data from Azure Monitor, Application Insights, VMs, containers. Use Kusto Query Language (KQL) to analyze logs. Stores data for retention (default 30 days, configurable). Exam tip: 'Query logs across multiple resources' = Log Analytics workspace. It's where logs go for analysis. |
