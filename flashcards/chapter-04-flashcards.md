## Chapter 4: Azure Regions, Availability Zones, and Resource Organization — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the maximum number of availability zones in a single Azure region? | 3 availability zones maximum per region. Each zone is one or more physically separate datacenters. Exam tip: Not all regions have availability zones; check regional availability. Deploying across 3 zones = 99.99% SLA for VMs. |
| 2 | When you delete a resource group, what happens to all resources inside it? | ALL resources are permanently deleted. Resource groups have lifecycle dependency with resources. Exam tip: This is heavily tested. No soft delete for general resources. Always a wrong answer: 'resources move to default group' or 'resources remain accessible'. |
| 3 | Region pairs vs Availability zones: disaster recovery strategy difference? | Availability zones = protect against DATACENTER failure within region (99.99% SLA). Region pairs = protect against ENTIRE REGION failure (geographic disaster recovery, 100+ miles apart). Exam tip: Question will describe failure scope—choose zones for datacenter, pairs for region-wide disaster. |
| 4 | Can resource groups be nested inside other resource groups? | NO. Resource groups cannot be nested. Each resource belongs to exactly ONE resource group. Exam tip: Common wrong answer is 'yes, for organizational hierarchy'—that's management groups, not resource groups. |
| 5 | Maximum depth of management group hierarchy (excluding root)? | 6 levels deep (excluding root management group) = 7 total levels including root. Exam tip: Root management group is automatically created per tenant. Each subscription can belong to only ONE management group at a time. |
| 6 | What are the THREE sovereign cloud regions in Azure? | 1) Azure Government (US gov agencies), 2) Azure China (operated by 21Vianet), 3) Azure Germany (being phased to standard regions). Exam tip: Sovereign = physically/logically isolated from public Azure. Choose Government for US compliance scenarios, China for China data residency. |
| 7 | Subscription vs Resource Group as RBAC scope—which is broader? | Subscription is broader. Hierarchy: Management Group > Subscription > Resource Group > Resource. RBAC inheritance flows DOWN. Exam tip: Assign at lowest necessary level. Common pattern: network team gets RBAC on resource group containing VNETs. |
| 8 | Does resource group location restrict where resources can be deployed? | NO. Resource group location = where METADATA is stored. Resources inside can be in ANY region globally. Exam tip: Common trap answer: 'must be same region'—false. Only consideration: metadata location for compliance. |
| 9 | Minimum distance between Azure region pairs? | At least 300 miles (480 km) apart. Ensures geographic disaster recovery (floods, earthquakes, power grid failures). Exam tip: Region pairs are predetermined by Azure (e.g., East US ↔ West US). You cannot choose custom pairs. |
| 10 | Which is the billing boundary in Azure: Management Group, Subscription, or Resource Group? | Subscription is the billing boundary. Each subscription has separate bill/quota/limits. Exam tip: Resource groups are for organization/RBAC, not billing. Management groups are for governance policies across subscriptions, not billing consolidation. |
| 11 | Can a single resource group span multiple subscriptions? | NO. Resource group exists within exactly ONE subscription. Resource groups cannot span subscriptions. Exam tip: To share resources across subscriptions, use management groups for governance or Azure Lighthouse for cross-tenant management. |
| 12 | What THREE properties define resource groups that the exam heavily tests? | 1) Lifecycle container (delete group = delete all resources), 2) RBAC scope boundary (assign permissions at RG level), 3) Cannot be nested (no parent-child RG relationships). Exam tip: If question mentions nested resource groups = wrong answer. |
